# SDK revision foundation and native verification

This is split part 1 of PR #15. It introduces no portable manifest, import planner,
merge-receipt migration or legacy merge recovery. The umbrella and recovery work
remain tracked by `pm-memory-1363` and `pm-memory-c3gv`.

`src/native-revision.ts` resolves the SDK's hydrated schema, serializes both
captured and pre-write documents through the SDK canonical writer, and binds the
item hash to native history length and history hash. The diagnostic version is
not an identity token. Capture refuses item/history disagreement and a corpus
that changed before its history could be bound.

Verification decodes and captures the same certified complete corpus while the
existing package lease is held, then releases the lease while evaluating claims.
Before publishing evidence it checks the exact SDK revision again in the native
pre-write hook. If the SDK returns a no-op without calling that hook, read-back
must still match. A changed revision is skipped; existing native fields remain.
Unchanged snapshots remain admissible as wall-clock time advances. Environment,
explicit invocation and per-call audit authors retain SDK precedence.

## Acceptance and evidence

| Acceptance | Evidence |
| --- | --- |
| Same timestamps cannot authorize changed native content | Seeded verification controls change fourteen semantic, provenance and opaque custom fields with fixed native timestamps. |
| ABA cannot reuse an old snapshot | The complete item hash returns to its old value while history advances; verification skips it. |
| Actual native writers are rechecked at publication | Independent Node SDK peers run after the initial guard, covering the real pre-write hook and SDK no-op read-back. |
| Read and write use identical normalization | Both live documents and SDK hook documents use the same SDK schema and canonical serializer. |
| Invalid or stale capture refuses | Real SDK history/file disagreement and a stale complete corpus are rejected. |
| Existing data remains usable | Unmodified item/history fixtures generated by published `pm-memory@2026.10.28` remain readable, verifiable and exportable. |
| Permission failures preserve state | A disposable Knowledge directory becomes read-only, the native error propagates, and exact permissions are restored in finally. |
| Audit author precedence survives extraction | Environment, explicit invocation and per-call authors are checked through real SDK history. |
| Existing concurrency contracts remain | Main's Store fencing and SDK writer leases are reused unchanged. Test launchers are capped at two workers; thresholds are unchanged. |

The previous-release fixture provenance records the public package version,
package integrity and archive SHA-256. The archive is untracked; only synthetic
text records and provenance are committed. No existing history was rewritten.

Revert receipts and full gate counts are recorded on
`pm-memory-native-revision-foundation` and in the part-1 PR body. Focused tests are
not a substitute for the complete npm and Bun release gates or exact-head CI.
